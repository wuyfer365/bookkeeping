当用户调用此技能时，对指定代码文件执行三轮注释检查。若带 `--fix` 参数，则检查后**自动修复**所有问题。

## 参数

| 参数 | 效果 |
|------|------|
| 无参数 | 仅检查，输出报告 |
| `--fix` | 检查 + 自动修复所有发现的注释问题 |
| `文件路径` | 只检查指定文件 |
| `目录路径` | 递归检查目录下所有 `.java` / `.js` / `.vue` |

## 检查维度

### 第一轮：缺失注释检查

1. **类/组件注释**：每个 class / interface / @Component / @Service / @RestController 是否有用途说明
2. **公共方法注释**：每个 public 方法是否有 JavaDoc / JSDoc，说明参数含义、返回值、异常情况
3. **核心私方法注释**：超过 10 行的 private 方法是否有功能说明
4. **关键代码块**：复杂算法、SQL 拼接、状态机、正则表达式等是否有行内注释解释「为什么这样做」
5. **DTO/VO/Entity 字段**：重要字段是否有注释说明含义和取值范围

### 第二轮：注释匹配检查

1. **语义一致性**：注释描述的行为与代码实际逻辑是否一致
2. **参数匹配**：`@param` 注释的参数名、类型、含义与签名是否对齐
3. **返回值匹配**：`@return` 注释的类型和含义与 return 语句是否一致
4. **过期注释**：代码已改但注释未同步更新（如：注释写"返回 List"但代码返回了 PageResult）
5. **异常声明**：`@throws` 是否覆盖了方法体中实际抛出的业务异常

### 第三轮：小白可读性检查

1. **术语解释**：业务术语（如"花销""分类树""级联删除"）首次出现时是否有解释
2. **缩写展开**：SQL 字段、变量名中的缩写是否在注释中展开（如 `exp_date` → "消费日期"）
3. **逻辑铺垫**：复杂方法前是否有一段「一句话概述」让读者先理解目的再读细节
4. **示例说明**：涉及金额计算、日期范围等容易误解的逻辑是否有举例

## 报告格式

```
# 注释质量检查报告

## 文件：<路径>

### ❌ 缺失注释（N 处）
| 行号 | 代码 | 问题 |
|------|------|------|
| L42 | `public void delete(Integer id)` | 未说明级联删除的副作用 |

### ⚠️ 注释不匹配（N 处）
| 行号 | 注释 | 实际代码 | 问题 |
|------|------|----------|------|
| L30 | `// 返回列表` | `return pageResult` | 注释说列表，实际返回分页对象 |

### 💡 小白可读性建议（N 处）
| 行号 | 当前注释 | 建议 |
|------|----------|------|
| L15 | `// 执行校验` | 建议展开为「校验花销金额 > 0 且不超过 99999999.99」 |

### ✅ 汇总

| 维度 | 缺失 | 不匹配 | 可读性建议 |
|------|------|--------|-----------|
| 后端 Java | N | N | N |
| 前端 JS/Vue | N | N | N |
```

## --fix 自动修复规则

当使用 `--fix` 时，在输出报告后立即逐文件执行修复：

### 修复缺失注释

1. **类级注释缺失** → 根据类名和代码逻辑生成 JavaDoc / JSDoc，说明职责和关键行为
2. **方法注释缺失** → 阅读方法体逻辑，为每个 public 方法生成完整 JavaDoc / JSDoc（含 `@param`、`@return`、`@throws`）
3. **关键代码块无注释** → 添加行内注释解释「为什么」，而非「做什么」
4. **字段无注释** → 根据字段名和 getter/setter 上下文补充含义说明

### 修复注释不匹配

1. **注释与代码不一致** → 根据实际代码修正注释
2. **过期注释** → 同步更新为当前逻辑
3. **缺少 @throws** → 根据方法体中 throw 语句补充

### 修复可读性

1. **术语无解释** → 首次出现的业务术语加注释说明
2. **缩写未展开** → 在定义处补充全称
3. **缺少一句话概述** → 在复杂方法前加概述行

### 修复后验证

每条修复用 Edit 工具精确替换，修复完成后重新运行测试确保不破坏代码。

## 检查范围

- 用户指定文件 → 只检查该文件
- 用户指定目录 → 递归检查目录下所有 `.java` / `.js` / `.vue` 文件
- 未指定 → 检查当前分支相对于 main/master 的所有变更文件
